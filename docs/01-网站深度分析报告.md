```
POST https://api.xiyanwl.asia/api/user/login
Body: {"account":"17587881293","password":"whm981004"}
响应: {"code":1,"msg":"登录成功","time":"<unix秒>","data":{"userinfo":{...},"token":"<36位>"}}
```

- token 长度 36 位（FastAdmin User token 插件风格）

## 7. 全站页面一致性审计报告（2026-10-25）

### 7.1 审计方法与口径

以 Playwright + Chromium（750×1334 视口、`isMobile:true`）对源站 `h5.xiyanwl.asia` 与本项目 dev server 做**同路由、同顺序、逐页 innerText 快照比对**，源站与本项目各 111 页全覆盖。

三处口径校正（否则会产生大量伪差异）：

| 校正项 | 源站现象 | 校正方式 |
|--------|---------|---------|
| placeholder 文本节点 | uni-app 的 `uni-input/uni-textarea` placeholder 会渲染成真实文本节点进入 innerText；本项目原生 `<input placeholder>` 不进入 | 源站采集时剔除 `.uni-input-placeholder,.uni-textarea-placeholder` |
| 图标字体字符 | 源站图标字体字符（`\ue601` `\ue62a` `\ue62f` `\ue63d` `\ue624` `\ue62a` `\ue807`）进入 innerText；本项目用 SVG | 比对前统一剔除 `[\ue000-\uf8ff]` |
| 源站网络超时 | 源站网络不稳时会渲染 "The connection timed out" 或**退化为首页内容**（含公告跑马灯），采集结果污染 | 判定含首页特征串（`【QBOX合成】`/`公告 【`/超时提示）即标记为伪差异并人工复核 |

### 7.2 伪差异分类（不需修复）

1. **源站采集时超时退化为首页** — 15 页（`index/index`、`market/detail`、`product/box`、`shop/detail/*`、`regift/regift` 等）。源站首次未登录采集（`audit.json`）中同一路由文本正常，交叉验证后确认。
2. **源站图标字体字符** — `webview/webview`、`my/enablingcenter`、`activeSelected` 等，仅差 `\ue601`。
3. **实时撮合数据波动** — 地板价、成交量、连续签到天数、VIP 条款条数等，均为源站实时值。
4. **源站正文使用 emoji** — `product/ruleDetail` 源站用 `🎫💰📦⏰📊👤📈🔄` 与 `1️⃣2️⃣` 做图标与序号；本项目按 **P0-1 规则**改为统一描边 SVG 图标 + 数字徽章（有意的不一致，属合规改进）。
5. **源站相对时间随时间推移** — `market/giftRecord` 的「N小时前」由 `createtime` 实时换算。源站快照采集于 3 小时前、当前已 5 小时前；本项目已改为**按 `createtime` 动态换算**（与源站同一规则），实时值同步。
6. **源站快照的瞬时加载态** — `my/flowDoc`、`my/address/list`、`order/beg/list`、`order/entrust/list` 源站快照末尾带「加载中」，是源站网络慢时接口未返回前的中间态；源站接口到达后终态分别为「暂无内容」「去添加收货地址」/ 空态插画，与本项目一致（已逐一实测复验）。本项目 mock 同步返回，故快照采集直接落在终态。
7. **uni-app 原生导航的隐藏文本副本** — `certification/certificationStatus` 源站 innerText 中「认证结果」出现两次（`uni-page-head__title` + 页面内 `u-navbar` 副本），实际渲染只显示一处（截图确认为单标题）；本项目只渲染一处，属 DOM 结构差异而非视觉差异。
8. **源站账号的实时数据变更（快照时间差）** — 第五轮复验时，对「残留 REAL 项」**重新抓取源站当前态**（延长等待至 9s + 3 次重试）后逐字符 diff，结论如下：

| 页面 | 表面差异 | 源站当前态实测结论 |
|------|---------|-----------------|
| my/address/list | 源站快照「加载中」 | 当前态「收货地址 去添加收货地址」→ 与本项目**逐字符一致** |
| order/beg/list | 源站快照「加载中」 | 当前态「我的求购 全部 求购中 已成交 已取消」→ **逐字符一致** |
| order/entrust/list | 源站快照「加载中」 | 当前态「我的委托 全部 委托中 已成交 已取消」→ **逐字符一致** |
| my/flowDoc | 源站快照「加载中」 | 当前态「流转记录 暂无内容」→ **逐字符一致** |
| my/vip | 本项目多出条款第 3 条后半 + 第 4 条 | 源站当前态**确为完整 4 条** → 本项目为**正确方** |
| order/list | 本项目多出 1 条「已取消 QBOX赛博龙 ¥310.00」订单 | 该订单是**本轮闭环验证时在源站真实创建**的订单；源站 `/api/order/order/orderList` 当前 `total=3` 且渲染出同样 3 条 → **完全一致**（非残留脏数据） |
| myCollection/collectionDetails | 「上链中」/「非法方式」 | 源站当前态逐字符一致 |
| market/giftRecord | 「14小时前」vs「15小时前」 | 源站当前态同为 15 小时前 → **逐字符一致** |
| product/ruleDetail | 源站 emoji 图标 | P0-1 有意不一致（唯一残留字符差异：源站 `⏰` `⏱️` 等 emoji 我方为 SVG 图标） |
| certification/certificationStatus | 源站「认证结果」重复 1 次 | uni-app 原生导航隐藏副本（第 7 类） |

> 结论：第五轮标为 REAL 的 10 项，**全部为快照时序/账号实时数据造成的伪差异**。重新采集源站当前态后，10 页中 **8 页逐字符零差异**，`ruleDetail` 仅剩 emoji→SVG 的 P0-1 有意差异，`certificationStatus` 仅剩框架隐藏副本差异。

### 9.2 整改手段一：SFC 样式外置（`<style scoped src>`）

**问题**：22 个页面的 `<style scoped>` 段长达 200~635 行，把样式与模板逻辑揉在一起。

**方案**：样式抽到 `src/styles/pages/<目录>-<文件名>.css`，页面内改为引用：

```html
<style scoped src="../../styles/pages/market-market-p0.css"></style>
<style scoped src="../../styles/pages/market-market-p1.css"></style>
```

**关键技术结论**：

| 结论 | 说明 |
|------|------|
| `scoped` 隔离性不依赖样式位置 | 隔离由 SFC 编译期注入的 `data-v` 哈希保证，跨文件拆分后**共享同一哈希**，样式隔离行为不变 |
| 一个 SFC 可挂多个 `<style scoped src>` 块 | 各块独立参与 px→vw 转换，实测均正确输出 vw |
| **`@import` 方案不可行** | pxToVw 插件仅对「作为构建入口的 .css 文件」生效；`@import` 的依赖文件在插件 transform 之前已被 Vite 解析，**px 不会被转换**（实测残留 `50px`）。故放弃 `@import`，改用多 `<style scoped src>` 块 |
| CSS 拆分边界 | 必须**按花括号配平**切分，不能按注释行号切（否则产生 `Unclosed block` 解析错误） |

**副作用验证**：产物 CSS 中 `px` 残留扫描，全站仅 `ruleDetail` 一处保留 px —— 该页源站本身为固定 px 布局（非 rpx 体系），源码已有 `/*@nopx*/` 显式豁免标记，符合预期。

```js
// 2) 必须用 addInitScript 在页面加载前写入 —— 事后写 localStorage 无效（路由守卫已判定未登录）
await ctx.addInitScript(t => { try { localStorage.setItem('token', t) } catch (e) {} }, tok)
```
