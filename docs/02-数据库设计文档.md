# QBOX 复刻项目 —— 数据库设计文档（MySQL 8 / utf8mb4）

> 依据：对原站 API 响应结构的实测抓包（详见 03-API接口文档），字段与原站返回值一一对应。
> 命名遵循原站 FastAdmin 风格（蛇形命名，fa_ 前缀省略，时间戳用 int unsigned 秒级）。
> 状态：v0.1（随页面推进持续补充；每页开发前先核对原站数据再落表，规则2/8）

- user_address: id, user_id, name, mobile, province, city, district, address, is_default
- diy_page: id, type(menu/notice...), category(home), name, content(JSON，实测首页菜单组 style=4 及 list[].image/path/name) —— 支撑首页金刚区可配置

## 3. ER 关系（核心链路）

```
user 1─N user_collection N─1 goods N─1 series
user 1─N order N─1 market_order N─1 user_collection
user_collection N─1 chain_task（task_id 关联，上链状态）
user 1─N user_option N─1 goods（藏品关注，「我的关注」板块数据源）
goods 1─N trade_record（成交/赠送流水，tradingInformation 数据源）
user 1─N beg_buy_order / entrust_order
user 1─N user_blind_box N─1 blind_box
user 1─1 user_realname / wallet_account(A/B/C 三行)
user 1─N sign_record / user_invite / vip_order / user_address
```

## 4. 设计约定

1. 全表 InnoDB，utf8mb4_general_ci；时间一律 int unsigned 秒级时间戳（与原站 time 字段一致）。
2. 金额 decimal(12,2)；涨跌幅 decimal(10,4)；展示红涨绿跌。
3. 软删除暂不引入（原站接口无 deleted_at 语义），用 status 字段表达状态。
4. 敏感字段（身份证、姓名）AES-256 加密存储，展示层打码（王*绵 / 520********838）。
5. 后续每开发一个页面，先抓原站该页接口数据 → 核对/补充表结构 → 再写代码（规则2）。
